# Assumptions & decisions

Ambiguities in the build plan and how they were resolved. Newest phase last.

## Phase 1 — Foundation

| # | Topic | Decision | Why |
|---|---|---|---|
| 1 | Local infra | **No local Postgres/Docker.** Dev and prod both use hosted **Neon** (Postgres + pgvector). The plan's "Docker Compose for local dev" is replaced; Compose returns in Phase 12 only for the deploy VM (FastAPI + n8n + Caddy). | Owner asked for a deployable setup without local services; Docker isn't installed. |
| 2 | Neon connection string | One variable, `DATABASE_URL`, holding Neon's **direct** (non `-pooler`) string exactly as Neon gives it. `app.config.to_async_url` converts it for asyncpg (`postgresql+asyncpg://`, `sslmode=require` → `ssl=True`, drops `channel_binding`). Alembic uses the same function. LangGraph's psycopg checkpointer (Phase 6) will derive its URL from the same value. | Avoids three copies of the same secret drifting apart; asyncpg prepared-statement caching conflicts with PgBouncer transaction pooling. |
| 3 | API key placement | The browser never sees `API_KEY`. Client components call `/api/backend/*`, a Next.js route handler that adds `X-API-Key` and streams the response (SSE-ready). Server env is `API_URL` + `API_KEY` (plan named `NEXT_PUBLIC_API_URL`; a public URL isn't needed with the proxy). | Plan requires the key be server-side only. |
| 4 | shadcn/ui | Primitives (`Button`, `Card`, badges) are written in shadcn's style (cva + `cn`, Radix `Slot`) and restyled per §13b, rather than generated by the shadcn CLI. More shadcn components can be added later as needed. | The §13b restyle replaces nearly all default styling anyway. |
| 5 | GSTIN in mockups | The mockup shows `29AABCT1332L1ZV`, which fails the GSTIN checksum. Seed data uses the checksum-valid `29AABCT1332L1ZA` for the same PAN. | Plan requires valid checksums; validation would otherwise flag our own vendor. |
| 6 | Seed data | Generated deterministically by `backend/scripts/build_seed_data.py` → `data/seed/*.json`; loaded by `scripts/seed.py` (replaces reference tables). Edge-case hooks: TechNova PO-2026-0042 at ₹1,100/unit (contract-rate case), BlueLeaf PO-2026-0035 with no GRN (ON_HOLD), Sharma PO-2026-0038 (split invoicing), CloudNest non-PO history coded to GL 6420 / CC-IT-01 (5 cases), Zenith Traders BLOCKED, Rangoli Packaging bank ••••6634 (bank-change case). | Reproducible demo data; fixtures for later phases. |
| 7 | Company GST state | Acme Retail Pvt Ltd is registered in Karnataka (29): Karnataka vendors charge CGST+SGST, others IGST. | From the plan's "Bengaluru". |
| 8 | Python toolchain on Windows | Python 3.12 via uv. The virtualenv is kept at `C:/Users/asus/.venvs/invoiceiq` (`UV_PROJECT_ENVIRONMENT`) — compiled extensions failed to load from a long project path (Windows MAX_PATH). Frontend uses `node-linker=hoisted` (`frontend/.npmrc`) for the same reason. | Windows path-length limits. |
| 9 | Later-phase pages | Sidebar routes that belong to later phases render a "Arrives in phase N" placeholder so navigation never 404s. | Keeps the shell complete and demoable. |

## Phase 2 — Test data & knowledge base

| # | Topic | Decision | Why |
|---|---|---|---|
| 10 | PDF tooling | Invoices are drawn with **ReportLab** (dev dependency) and "scanned" with **PyMuPDF** + **Pillow** (rasterise → greyscale → skew → noise/speckles → blur → low-quality JPEG → image-only PDF). PyMuPDF and Pillow are runtime dependencies because Phase 3 uses them for text-layer detection and page images. ReportLab has no type hints, so mypy ignores its imports; PyMuPDF calls are excluded from the untyped-call check. | Pure Python, works on Windows and ARM Linux, no system packages (wkhtmltopdf/Chrome). |
| 11 | Rupee sign | Documents print **"Rs." / "INR"** instead of ₹ — the built-in PDF fonts have no ₹ glyph, and many real Indian invoices do the same. Extraction must normalise both. Knowledge-base docs (Markdown) use ₹. | Avoids bundling a TTF font; realistic. |
| 12 | Seed additions | Added GRN-0315…0321 (so the clean cases on PO-2026-0045…0049 can 3-way match) and PO-2026-0050 (Kaveri, catalogue) / PO-2026-0051 (Malabar, cabinets) with GRNs, for the IGST-error and math-error cases. Neon was reseeded. Existing edge-case hooks (PO-2026-0035 has no GRN, etc.) are unchanged. | Each test invoice needs its own PO so cases don't interfere. |
| 13 | Case specs are code | Every test document is a spec in `backend/scripts/invoice_specs.py` (lines, vendor, printed deviations, expected outcome). Amounts are computed from lines, so ground truth can't drift from the PDF; a test fails if the committed PDFs/JSON are stale. | Single source of truth for Phase 3 fixtures, Phase 4 rule tests and Phase 11 eval. |
| 14 | `expected.decision` meaning | The decision **before any human acts**. An approval gate (amount > ₹5 lakh, non-PO invoice) gives `NEEDS_REVIEW` with `approvals` listing the roles; `final_decision` is the outcome once the intended human action happens. Touchless `APPROVED` means no gate fired (policy §9). | Plan says "amount > approval limit → NEEDS_REVIEW"; applied the same rule to the non-PO approval. |
| 15 | Outcomes the plan left open | Unknown supplier (valid GSTIN, not in master) → `ON_HOLD` (missing master data; the agent may not create vendors). Blocked vendor → `REJECTED`. Arithmetic off by > ₹1 → `REJECTED` (vendor must reissue). Quotation and credit note → `REJECTED` (credit notes are adjusted against the original, not paid). Wrong GST head (IGST intra-state) → `NEEDS_REVIEW` for the tax team. Split invoice #3 raises both `OVER_PO_BALANCE` and `QTY_VARIANCE` (340 reams billed vs 300 ordered/received). | Encoded in `ap-policy.md` so the rules and their citations agree. |
| 16 | ERP read-back case | `malabar-erp-mismatch` passes every rule; its ground truth carries `erp_fault: amount_minus_one_paisa`, which the mock ERP (Phase 8) will honour in demo mode so the read-back check fails. Proposed exception category for this: `ERP_MISMATCH` (not in the plan's list). | The fault is in the ERP, not the PDF, so it has to be injected. |
| 17 | Policy numbers | Price tolerance 2% per line and ₹5,000 per invoice; quantity tolerance 0; freight ≤ ₹1,000; duplicate window 30 days; approval matrix ≤ ₹5 L none, ≤ ₹25 L Finance Manager, above that + CFO; non-PO → Department Head (+ Finance Manager above ₹1 L); bank change → AP Manager + Finance Controller. These are the defaults the Phase 8 Operating Procedure will start from. | Plan gave examples, not values. |
| 18 | Recurring invoices vs duplicate window | CloudNest bills the same ₹49,560 every month. Oct 1 → Nov 1 is 31 days, just outside the 30-day window. Phase 4's suspected-duplicate rule should also compare service periods so monthly subscriptions aren't flagged. | Noted now so the rule isn't written naively. |
| 19 | Knowledge base format | Markdown with YAML front matter (`doc_type`, `vendor_id`, `valid_from/valid_to`, …) and numbered `##`/`###` headings, so `MarkdownHeaderTextSplitter` yields citable sections like `[contracts/technova §2.1]`. Contracts include mid-year rate amendments (Sharma paper, BlueLeaf line haul, Rangoli boxes) and one terminated contract (Zenith). A test checks that every citation in the ground truth resolves to a real section. | Grounded citations in Phase 5. |
